# 信息公开与发布规范

HVAC & Energy Systems Wiki 面向公开技术传播。内容应以**公开、可验证、可追溯、可复用**为基本要求，同时严格保护企业知识产权、客户信息与未公开工程细节。

## 1. 项目定位

本项目是工程学习与开放知识整理项目，以暖通空调、制冷、热泵和建筑及工业节能为当前重点，并逐步连接控制、仿真、能源优化与系统工程。

工作过程中接触的企业资料只能作为知识理解来源。公共页面必须经过知识点提取、知识泛化、公开来源验证和自主重写。

## 2. 可公开内容

优先使用以下来源：

- 国家标准、行业标准、公开规范与指南；
- 正式出版教材、公开课程与学术论文；
- 政府、科研机构、行业协会公开发布资料；
- 厂商官网、公开样本、公开白皮书与公开案例；
- 作者基于公开资料形成的原创分析、计算和图示；
- 已充分匿名化、抽象化且无法反向识别具体企业或客户的工程经验。

## 3. 不应公开内容

以下内容不得进入公开仓库：

- 企业内部设计图纸、BOM、结构尺寸、供应商信息与成本数据；
- 未公开设备参数、实验数据、性能曲线、控制策略和内部算法；
- 客户、项目、地址、联系方式、合同及商业谈判信息；
- 内部会议纪要、培训原件、流程文件和未公开制度；
- 任何可能使第三方逆向识别企业产品设计、生产方法或商业策略的组合信息。

## 4. 工程案例写作规则

工程案例优先采用公开来源。推荐按照以下结构组织：

1. 工程背景；
2. 系统边界与已知条件；
3. 主要问题；
4. 物理与系统原因分析；
5. 公开可验证的解决方案；
6. 性能评价方法；
7. 工程启示与适用边界；
8. 参考来源。

如案例来自实际工作经验，应删除所有可识别信息，并将具体参数转化为公开范围、典型值或无量纲关系。若仍存在知识产权风险，则不发布。

## 5. 技术表述要求

- 区分事实、文献结论、公开厂商声明、作者分析与推断；
- 对外部数据、标准条款和关键技术结论提供来源；
- 不将单一案例经验直接写成普遍规律；
- 涉及参数时说明工况、边界条件和适用范围；
- 专业术语首次出现时，优先采用“中文名称（English Full Name，ABBR）”。

## 6. 发布流程

建议执行：

**资料筛选 → 公开性判断 → 重写与脱敏 → 来源核验 → 技术审查 → Public-Safe Review → Git 提交 → 构建检查 → 发布**

提交前同时参考仓库根目录中的 SECURITY_REVIEW.md 检查清单；该文件属于仓库审查材料，不随网站发布。
