# 交流与问答

这里用于提交学习疑问、工程概念讨论、页面勘误和内容建议。留言与提问通过 GitHub Issue 表单进入，管理员在核验后回复；经过整理的通用知识才会进入正式答疑归档或对应章节。

> 提交内容会公开显示。请勿填写客户信息、项目地址、内部图纸、BOM（Bill of Materials，物料清单）、未公开参数、报价、账号或其他敏感信息。

## 两类提交入口

| 入口 | 适合内容 | 处理方式 |
| --- | --- | --- |
| [提交技术问题](https://github.com/linkparkxin/energy-systems-wiki/issues/new?template=technical-question.yml) | 制冷、热泵、换热器、控制、仿真和工程判断等问题 | 管理员核验问题边界后答复，必要时整理进知识正文 |
| [提交内容建议或勘误](https://github.com/linkparkxin/energy-systems-wiki/issues/new?template=content-feedback.yml) | 公式、链接、图片、术语、事实或排版问题 | 管理员复核来源与修改影响，再决定是否发布修订 |

也可以[查看全部公开问题与讨论](https://github.com/linkparkxin/energy-systems-wiki/issues)。Issue 是 GitHub 上的公开问题记录，提交时间、回复、状态和处理过程都会保留在对应页面。

## 答疑如何进入知识库

答疑区分为“交流记录”和“正式知识”两种状态：

1. 读者提交问题或建议，形成一条公开 Issue 记录。
2. 管理员判断问题是否属于公开知识范围，并检查是否包含企业敏感信息。
3. 管理员在 Issue 中给出初步答复；涉及公式、标准、参数或工程结论时，先补充必要的来源和适用边界。
4. 对具有长期学习价值的问题，管理员将内容重新组织为原创、可复现的 Markdown 文本，放入对应章节或[答疑归档](/community/qa-log)。
5. 正式内容通过 Git 提交发布，网站由现有 GitHub Actions 自动构建。

目前已有的制冷与热泵答疑可直接阅读：[制冷与热泵工程答疑](/knowledge/refrigeration/13-field-faq)。

## 版本与权限规则

正式知识页面只从仓库的 Markdown 源文件生成。读者的 Issue 评论不会直接改动正文；正文更新由管理员手动整理、审阅和合并，每次变更都形成 Git commit，可查看差异、责任人和历史版本。

建议管理员在 GitHub 仓库的 Settings → Rules 中为 \`main\` 设置规则集：

- 禁止未经审核的直接推送；
- 要求通过 Pull Request（拉取请求）合并；
- 禁止强制推送；
- 仅允许管理员或指定维护者合并正式内容；
- 要求 GitHub Actions 构建检查通过后再合并。

Issue 本身可能显示作者编辑标识，因此它适合作为交流记录，不作为正式知识版本的唯一依据。需要固定版本的答复，应归档到 Markdown 并由管理员提交。

## 提交前检查

请先确认：

- 问题描述包含足够的背景、现象和目标；
- 温度、压力、流量、功率等数据注明单位和测点；
- 公式中的变量、边界条件和计算口径清楚；
- 图片、表格和引用来源具有公开使用或自主创作依据；
- 不包含内部产品参数、客户资料和未公开工程数据。

本栏目只提供公开工程知识交流，不替代设备厂家说明书、现场安全规程、法定标准或专业人员的现场判断。
