# 讨论区维护与部署

本项目的网页由 GitHub Pages 静态发布，静态文件本身不能安全保存留言，也不能把管理员密钥放在浏览器端。因此，开放式讨论区采用 Waline 客户端加独立服务端和数据库的结构。

## 建议的权限模型

| 操作 | 普通参与者 | 管理员 |
| --- | --- | --- |
| 创建问题 | 允许 | 允许 |
| 回复和补充 | 允许 | 允许 |
| 修改他人内容 | 不允许 | 允许 |
| 删除或隐藏内容 | 不允许 | 允许 |
| 修改知识库 Markdown | 不允许 | 通过 Git 提交 |
| 发布正式答疑 | 不直接发布 | 通过 Git 提交 |

为了保留讨论过程，普通用户的补充内容建议以新回复保存。管理员删除内容时，优先采用逻辑删除或隐藏方式，并保留操作时间和原因；只有在法律、隐私或安全要求下才进行彻底删除。

## 服务端配置

管理员需要先部署 Waline 服务端和数据库，再将服务端公开地址写入构建环境变量：

~~~text
VITE_WALINE_SERVER_URL=https://your-waline-server.example.com
~~~

该地址可以公开写入前端构建结果。数据库连接串、管理员密码、邮件服务密钥和内容安全服务密钥必须只保存在服务端环境变量中，不能写入本仓库。

服务端首次部署完成后，应立即完成管理员注册并修改默认凭据。Waline 官方文档提供了服务部署、数据库连接和管理后台说明：[Waline Get Started](https://waline.js.org/en/guide/get-started/)。

## 讨论区运行策略

前端当前使用以下策略：

- 关闭强制登录；
- 只要求填写昵称；
- 不要求填写邮箱和个人主页；
- 每页默认显示 10 条留言；
- 单条留言限制在合理长度内；
- 以当前网页路径区分不同文章的讨论串；
- 服务端异常时显示友好提示，不影响正文阅读。

服务端应进一步配置：

- 普通参与者只能创建和回复；
- 普通参与者不能删除他人内容；
- 管理员拥有删除、隐藏、恢复和必要编辑权限；
- 开启反垃圾和敏感内容过滤；
- 定期备份数据库；
- 不收集非必要的真实姓名、手机号和精确位置。

## 版本归档策略

讨论记录保存在讨论服务数据库中，正式知识内容保存在 Git 中。二者职责不同：

| 内容 | 保存位置 | 版本方式 |
| --- | --- | --- |
| 原始问题与回复 | Waline 数据库 | 创建时间、回复关系和数据库备份 |
| 管理员隐藏记录 | Waline 管理日志或备份 | 操作时间和处理原因 |
| 正式知识答案 | docs/ Markdown | Git commit |
| 正式图片和示意图 | docs/ assets | Git commit |
| 重大知识修订 | Git commit 与更新记录 | 可比较、可回退 |

归档时应保留原始讨论链接或讨论编号，但正文中不得出现内部项目名称、客户信息和未公开参数。

## 每月维护清单

- 检查讨论服务是否能够正常提交和加载回复；
- 检查数据库备份是否可恢复；
- 清理广告、恶意内容和重复刷屏；
- 检查是否出现企业敏感信息；
- 将高价值讨论整理到对应章节；
- 检查 GitHub Actions 构建状态；
- 检查讨论服务端和依赖版本的安全更新。

如暂时没有配置服务端，页面会显示“讨论区服务尚未配置”，不会影响知识库其他页面的访问。
